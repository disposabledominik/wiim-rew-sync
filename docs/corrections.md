# Assumption Corrections Ledger

*Whenever an assumption from the specifications fails during implementation, log it here. This file acts as the project memory.*

| Date | Assumption | Failure / Observation | Root Cause | Implemented Solution |
| --- | --- | --- | --- | --- |
| 2026-06-12 | All WiiM devices have `project` field starting with `WiiM_`. | WiiM Mini reports `project: "Muzo_Mini"` — a legacy/OEM name. | WiiM Mini uses older firmware branding from before the WiiM rebrand. | Added `Muzo_Mini` to `WIIM_PROJECT_PREFIXES` in `capability_prober.py`. |
| 2026-06-12 | mDNS TXT records include DeviceName, project, and Release fields. | TXT records on tested devices are empty for these fields. | WiiM mDNS services don't populate TXT record metadata. | Added `_enrich_device()` in `discovery_module.py` to call `getStatusEx` after mDNS resolves IPs. |
| 2026-06-12 | Source names in `EQGetLV2SourceBandEx` are case-insensitive. | Source names are CASE-SENSITIVE. `hdmi` (lowercase) returns the L/R channel-mode slot; `HDMI` (uppercase) returns the Stereo slot. Same source, different case = different PEQ data. | The WiiM API uses case to distinguish channel-mode storage slots for the same physical input. | Document in API notes. Users must use the exact case the WiiM app uses (typically uppercase for physical inputs: HDMI, Ethernet; lowercase for logical: wifi, bluetooth, line-in, optical). |
| 2026-06-12 | WiiM devices have 10 PEQ bands (letters a-j). | WiiM Amp Ultra (firmware 20260409) has 12 bands (letters a-l). | Newer firmware expanded the band count from 10 to 12. | Updated `_BAND_LETTERS` to `"abcdefghijkl"`. The `max_filters` capability should be probed dynamically rather than hardcoded. |
| 2026-06-12 | WiiM PEQ mode values are: -1=OFF, 0=LS, 1=PEAK, 2=HS. | Additional modes exist: 3=LP (Low-Pass), 5=HP (High-Pass). | Newer firmware added LP/HP filter types to the PEQ engine. | Added modes 3 and 5 to `_MODE_MAP`. Added "LP" and "HP" to `FilterType` literal. |
| 2026-06-12 | Source enumeration possible via API. | WiiM API returns valid PEQ data for ANY source name (even non-existent physical inputs). No API endpoint exists to enumerate actual physical inputs. `getStatusEx` has no `InputList` field on tested devices. | The PEQ engine has internal slots for all possible sources regardless of hardware. | OPEN ISSUE: Need alternative approach to source discovery. Current workaround: probe canonical names and show all. User must know their device's physical inputs. |
| 2026-06-14 | RoomFit uses dedicated commands: `getRoomFitStatus`, `getRoomFitBands`, `setRoomFitBands`. | These commands do not exist. RoomFit uses the standard LV2 PEQ command family (`EQGetLV2SourceBandEx`, `EQSetLV2SourceBand`, `EQv2GetNewList`) with `"EQLevel": 2` added to the JSON payload. Profile CRUD also uses standard commands (`EQSourceSave`, `EQv2Delete`, `EQv2SourceLoad`) with `EQLevel: 2`. | RoomFit is not a separate subsystem — it's a second EQ level within the existing LV2 plugin architecture. The original assumptions were based on speculative community docs. | Code needs updating: `capability_prober._probe_roomfit()` and `wiim_adapter.read_roomfit()`/`write_roomfit()` must use the real commands. Tests need fixture updates. Documented in `wiim_api_notes.md`. |
| 2026-06-14 | RoomFit `EQGetLV2SourceBandEx` + `EQLevel: 2` returns the DSP-active profile's bands (same as PEQ reads). | It returns the API "working buffer" — which is the last profile loaded via `EQv2SourceLoad`, NOT the DSP-active state. Without a prior load, returns a flat default template regardless of what the app shows as active. Buffer is device-global, persistent across connections and reboots (stored in flash). Not cleared by profile deletion, profile switching, toggling RoomFit, or device reboot. Only overwritten when a profile is actively edited/calibrated via the WiiM app or loaded via API. | RoomFit has three layers: profile storage, API working buffer, and DSP-active state. PEQ (EQLevel 1) conflates buffer and DSP; RoomFit (EQLevel 2) separates them. | Read workflow must first load the target profile via `EQv2SourceLoad` before reading bands. Buffer is harmless to WiiM app (app ignores it for display/playback). Documented in `wiim_api_notes.md`. |
| 2026-06-14 | RoomFit direct writes (`EQSetLV2SourceBand` + `EQLevel: 2`) apply changes to the DSP immediately (like PEQ writes). | Writes only modify the API working buffer. Must be followed by `EQSourceSave` to persist. Saving to the ACTIVE profile name deactivates RoomFit; saving to a NEW profile name does NOT deactivate. Buffer retains data after save (not cleared). Delete of non-active profiles also does not deactivate. | RoomFit is profile-based. The DSP activation mechanism is internal to the WiiM app. Overwriting the active profile triggers a reload/deactivation cycle; creating a new profile is non-disruptive. | Write workflow: load → modify buffer → save. If overwriting active profile: warn user about deactivation. If saving as new name: no disruption. Level 4 confirmed with these semantics. |
| 2026-06-14 | WiiM Mini (no RoomFit hardware) will reject RoomFit commands or return "unknown command". | WiiM Mini silently accepts ALL RoomFit commands (`EQv2GetNewList`+EQLevel:2, `EQGetLV2SourceBandEx`+EQLevel:2, `EQSourceSave`+EQLevel:2, `EQv2Delete`+EQLevel:2) with HTTP 200 and valid-looking responses. The probe reaches `roomfit_level = 4` even though the device has no RoomFit capability. Band reads return data with `EQStat: Off` but the response structure is valid. Profile save/delete return "OK". | The WiiM Mini's API never rejects unknown EQLevel values — it just processes the command against an inactive/empty subsystem. There is no API-level distinction between "device has RoomFit but it's off" and "device doesn't have RoomFit at all." | OPEN ISSUE: Currently the Mini reports `roomfit_level = 4`. This is harmless in practice (RoomFit reads return empty/off data, writes persist to an unused profile store), but is semantically incorrect. Possible fix: after `EQSourceSave`, verify the profile appears in `EQv2GetNewList` (round-trip check). Low priority since Mini RoomFit operations are no-ops. |
