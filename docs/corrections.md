# Assumption Corrections Ledger

*Whenever an assumption from the specifications fails during implementation, log it here. This file acts as the project memory.*

| Date | Assumption | Failure / Observation | Root Cause | Implemented Solution |
| --- | --- | --- | --- | --- |
| 2026-06-12 | All WiiM devices have `project` field starting with `WiiM_`. | WiiM Mini reports `project: "Muzo_Mini"` — a legacy/OEM name. | WiiM Mini uses older firmware branding from before the WiiM rebrand. | Added `Muzo_Mini` to `WIIM_PROJECT_PREFIXES` in `capability_prober.py`. |
| 2026-06-12 | mDNS TXT records include DeviceName, project, and Release fields. | TXT records on tested devices are empty for these fields. | WiiM mDNS services don't populate TXT record metadata. | Added `_enrich_device()` in `discovery_module.py` to call `getStatusEx` after mDNS resolves IPs. |
| 2026-06-12 | Source names in `EQGetLV2SourceBandEx` are case-insensitive. | Source names are CASE-SENSITIVE. `hdmi` (lowercase) returns the L/R channel-mode slot; `HDMI` (uppercase) returns the Stereo slot. Same source, different case = different PEQ data. | The WiiM API uses case to distinguish channel-mode storage slots for the same physical input. | Document in API notes. Users must use the exact case the WiiM app uses (typically uppercase for physical inputs: HDMI, Ethernet; lowercase for logical: wifi, bluetooth, line-in, optical). |
| 2026-06-12 | WiiM devices have 10 PEQ bands (letters a-j). | WiiM Amp Ultra (firmware 20260409) has 12 bands (letters a-l). | Newer firmware expanded the band count from 10 to 12. | Updated `_BAND_LETTERS` to `"abcdefghijkl"`. The `max_filters` capability should be probed dynamically rather than hardcoded. |
| 2026-06-12 | WiiM PEQ mode values are: -1=OFF, 0=LS, 1=PEAK, 2=HS. | Additional modes exist: 3=LP (Low-Pass), 5=HP (High-Pass). | Newer firmware added LP/HP filter types to the PEQ engine. | Added modes 3 and 5 to `_MODE_MAP`. Added "LP" and "HP" to `FilterType` literal. |
| 2026-06-12 | Source enumeration possible via API. | WiiM API returns valid PEQ data for ANY source name (even non-existent physical inputs). No API endpoint exists to enumerate actual physical inputs. `getStatusEx` has no `InputList` field on tested devices. | The PEQ engine has internal slots for all possible sources regardless of hardware. | OPEN ISSUE: Need alternative approach to source discovery. Current workaround: probe canonical names and show all. User must know their device's physical inputs. |
